#+TITLE: Build Simplification
#+STARTUP: overview

* Vision

Pure ~swift build~ + ~justfile~ is the sole build system. No Xcode
project, no xcconfigs, no pbxproj. Every piece of code lives in a
single root-level ~Package.swift~ (7 SPM targets) or is generated by a
script from a flat manifest.

Done so far: 91 extension dylibs → single SPM static library; LuaSkin →
SPM; per-extension Xcode targets removed; hs CLI → SPM; Lua file
copying → manifest-driven; ~-undefined dynamic_lookup~ removed; all
compiler warnings enabled; PCH removed; Package.swift switched to
auto-discovery; manifests unified; Xcode build system removed entirely
(no pbxproj, no xcconfigs, no project.yml); Run Script phases → justfile;
3 SPM packages → 1 root ~Package.swift~; all 4 XIBs → programmatic UI;
xcassets → pre-compiled ~.icns~; entitlements → ~codesign~ in justfile;
App Intents removed; macOS 26 deployment floor; deprecated APIs replaced;
CocoaLumberjack → ~os_log~; CocoaHTTPServer → Network.framework;
lsqlite3 → Swift sqlite3; Sundown → swift-markdown; CocoaAsyncSocket →
Network.framework.

* Investigated — not worth doing

** SKIP Make generators Xcode build-time phases
   Not feasible — generator outputs are SPM package sources (compiled
   before Xcode target phases run) and xcfilelists (consumed before the
   build starts). Pre-commit hook + CI is the correct enforcement point.

** DEFER Make ~BuildDocs~ a workspace SPM dependency
   Only practical option (Option C: ~.executableTarget~ invoked by Run
   Script) adds ~swift-argument-parser~ to workspace resolution for
   marginal benefit. Current out-of-band build works fine.
