#+TITLE: Build Simplification
#+STARTUP: overview

* Vision

Make ~swift build~ the primary tool for everything that doesn't need an
~.app~ bundle, and reduce ~xcodebuild~ / ~project.pbxproj~ to the bare
minimum required to ship a signed, sandboxed AppKit application. Every
piece of code should live in an SPM package or be generated by a script
from a flat manifest — no Xcode-UI-only state.

Done so far: 91 extension dylibs → single SPM static library; LuaSkin →
SPM; per-extension Xcode targets removed (96 → 3); hs CLI → SPM; Lua
file copying → manifest-driven; script sandboxing enabled; ~-undefined
dynamic_lookup~ removed; xcconfigs collapsed 6 → 3; all 15 compiler
warnings enabled; PCH removed; incremental builds fixed; pbxproj cut
~85 %.

* Investigated — not worth doing

** SKIP Extract ~HammerspoonCore~ SPM package
   Only 5 files (168 lines) are decoupled enough to extract. Too small
   to justify the structural overhead.

** SKIP Replace ~.xib~ files with programmatic UI
   Controllers are coupled to app-level singletons regardless of XIBs.
   Half-day effort for low benefit.

** SKIP Make generators Xcode build-time phases
   Not feasible — generator outputs are SPM package sources (compiled
   before Xcode target phases run) and xcfilelists (consumed before the
   build starts). Pre-commit hook + CI is the correct enforcement point.

** DEFER Make ~BuildDocs~ a workspace SPM dependency
   Only practical option (Option C: ~.executableTarget~ invoked by Run
   Script) adds ~swift-argument-parser~ to workspace resolution for
   marginal benefit. Current out-of-band build works fine.
