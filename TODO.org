#+TITLE: Build Simplification
#+STARTUP: overview

* Vision

Make ~swift build~ the primary tool for everything that doesn't need an
~.app~ bundle, and reduce ~xcodebuild~ / ~project.pbxproj~ to the bare
minimum required to ship a signed, sandboxed AppKit application. Every
piece of code should live in an SPM package or be generated by a script
from a flat manifest — no Xcode-UI-only state.

Done so far: 91 extension dylibs → single SPM static library; LuaSkin →
SPM; per-extension Xcode targets removed (96 → 3); hs CLI → SPM; Lua
file copying → manifest-driven; script sandboxing enabled; ~-undefined
dynamic_lookup~ removed; xcconfigs collapsed 6 → 3; all 15 compiler
warnings enabled; PCH removed; incremental builds fixed; Package.swift
switched to auto-discovery; manifests unified; pbxproj cut ~85 %.

* TODO

** TODO Merge 19 core ~.m~ files into ~HSExtensions~ SPM target
   Move all ~Hammerspoon/*.m~ sources into the existing ~HSExtensions~
   SPM package instead of creating a separate ~HammerspoonCore~ target.

   Why merge instead of separate package: the core files and extensions
   already have circular header dependencies (extensions import
   ~variables.h~, ~MJLua.h~; core calls ~HSExtensionsRegisterAll()~).
   Keeping them in one SPM target eliminates dead-stripping risk for
   ~HSExtensionsRegistry.m~, avoids public-header API decisions, and
   removes the need for ~-force_load~ linker flags.

   Steps:
   1. Symlink ~Hammerspoon/~ source files into ~Sources/HSExtensions/~
      (the ~Hammerspoon~ symlink already exists for headers).
   2. Remove the ~"Hammerspoon"~ entry from ~exclude:~ in Package.swift
      so SPM compiles the 19 ~.m~ files. Add excludes for non-source
      files in ~Hammerspoon/~ (~.xib~, ~.xcassets~, ~.plist~,
      ~.entitlements~, ~.pch~, ~.sdef~, ~.intentdefinition~, ~.rtf~,
      ~.pdf~, ~.json~, ~.lua~, ~.icns~).
   3. Remove the 19 source files from the Xcode ~Sources~ build phase
      (they're now compiled by SPM).
   4. Keep XIBs, asset catalog, ~Intents.intentdefinition~, ~Info.plist~,
      entitlements, and resources in the Xcode target.
   5. Add any needed ~cSettings~ (header search paths for ~libxml2~,
      framework links for ~CoreServices~, etc.).

   Result: Xcode compiles zero ~.m~ files — purely assembles the bundle.

** TODO Move Run Script phases into ~just~ recipes
   The 4 shell-script build phases become ~just~ recipes:
   1. ~just _version~ — update version/build numbers via git tags.
   2. ~just _docs~ — compile docs.json (conditional on BuildDocs).
   3. ~just _hs-cli~ — build + codesign the ~hs~ CLI.
   4. ~just _copy-lua~ — manifest-driven Lua file copy.

   The ~just build~ recipe becomes:
   ~just _version && just _docs && just _hs-cli~ → ~xcodebuild~ → ~just _copy-lua~.
   Steps 1-3 run before xcodebuild (no ~$TARGET_BUILD_DIR~ needed).
   Step 4 runs after (needs the ~.app~ bundle path).

   Remove the 4 ~PBXShellScriptBuildPhase~ entries from pbxproj.

   - Compiles 3 XIBs + 1 asset catalog + 1 intent definition
   - Bundles ~Info.plist~, entitlements, resources
   - Weak-links ~SkyLight~, ~DisplayServices~, ~CoreDisplay~
   - Hosts test + UI test targets

   Generate from a ~60-80 line YAML. Delete pbxproj from version

** SKIP Replace ~.xib~ files with programmatic UI
   Controllers are coupled to app-level singletons regardless of XIBs.
   Half-day effort for low benefit.

** SKIP Make generators Xcode build-time phases
   Not feasible — generator outputs are SPM package sources (compiled
   before Xcode target phases run) and xcfilelists (consumed before the
   build starts). Pre-commit hook + CI is the correct enforcement point.

** DEFER Make ~BuildDocs~ a workspace SPM dependency
   Only practical option (Option C: ~.executableTarget~ invoked by Run
   Script) adds ~swift-argument-parser~ to workspace resolution for
   marginal benefit. Current out-of-band build works fine.
