#+TITLE: Build Simplification

* Vision

Pure ~swift build~ + ~justfile~ is the sole build system. No Xcode
project, no xcconfigs, no pbxproj. Every piece of code lives in a
single root-level ~Package.swift~ (6 SPM targets) or is generated by a
script from a flat manifest. Lua runtime provided by ~LuaSwift~ package
dependency — no vendored C sources.

Done so far: 91 extension dylibs → single SPM static library; LuaSkin
removed entirely (replaced by LuaSwift + raw Lua C API); per-extension
Xcode targets removed; hs CLI → SPM; Lua file copying →
manifest-driven; Xcode build system removed entirely; all XIBs →
programmatic UI; all vendored C libraries replaced (CocoaHTTPServer →
Network.framework, lsqlite3 → Swift sqlite3, Sundown → swift-markdown,
CocoaAsyncSocket → Network.framework, CocoaLumberjack → os_log,
LuaSkin → LuaSwift).

* TODO — Migrate raw Lua C API (CLua) to idiomatic LuaSwift API
:PROPERTIES:
:STATUS: PLANNING
:OWNER: agent-pipeline
:END:

  Origin: surfaced while evaluating ecritum (see ~ECRITUM_PLAN.org~ B1). The
  ergonomic win attributed to ecritum is actually available today by adopting
  LuaSwift's idiomatic Swift API — no engine swap, no capability loss.

** Context / why
   Extensions were ported from Hammerspoon's C by transliterating the Lua C API
   into Swift + ~CLua~, rather than rewriting onto LuaSwift's idiomatic Swift
   API. Result (measured 2026-06-10):
   - 112 files ~import CLua~; idiomatic LuaSwift API used in ~1 file.
   - Raw call-site counts in ~Sources/HSSwiftExtensions/~: ~lua_setfield~ ×1330,
     ~lua_pushany~ ×948, ~luaL_checkudata~ ×577, ~lua_pop~ ×558,
     ~lua_pushboolean~ ×550, ~luaL_setfuncs~ ×210, ~luaL_unref~ ×206,
     ~luaL_ref~ ×197, ~lua_createtable~ ×186, …
   - Home-grown ~lua_pushany~/~lua_tovalue~ duplicate LuaSwift's
     ~push(any:)~/~tovalue~/~toany~.

   LuaSwift (already a dependency — the ~Lua~ product) provides: ~Metatable<T>~,
   ~register(Metatable<T>)~, ~push(closure:)~, typed ~push<Args,Ret>(closure:)~,
   ~push(userdata:)~, ~tovalue<T>()~, ~toany~, ~LuaValue~, ~ref()~, ~Pushable~,
   ~PushableWithMetatable~. Adopting these cuts boilerplate and removes whole
   classes of stack-discipline / ref-lifetime / force-cast bugs while keeping
   Lua 5.4, userdata, metatables, and synchronous main-thread callbacks intact.

** Goals / non-goals
   - Goal: replace raw ~CLua~ boilerplate with idiomatic LuaSwift in extension
     registration, value conversion, userdata/metatables, and registry refs —
     incrementally, module by module, each step independently buildable and
     verifiable.
   - Goal: deduplicate home-grown conversion against LuaSwift equivalents where
     behavior provably matches (esp. binary-safe strings, NUL handling).
   - Non-goal: any change to public Lua API/behavior, the threading model, the
     bundle layout, or the engine.
   - Non-goal: a big-bang rewrite. Every step must ~just build~ + pass its
     focused tests before the next starts.

** Verification harness (every step uses this)
   - Resources: ~mise exec -- just test-resources~
   - Build: ~mise exec -- just build~
   - Focused tests:
     ~SDK_PATH="$(xcrun --show-sdk-path)" COSMIC_HAMMER_TEST_RESOURCES="$(pwd)/build/test/Cosmic Hammer.app/Contents/Resources" swift test -Xlinker -F -Xlinker "${SDK_PATH}/System/Library/PrivateFrameworks" --filter <Suite>~
   - Generated glue stays consistent: ~just check-generated~
   - Each step adds/keeps regression tests proving identical Lua-visible behavior
     (userdata identity, metatable methods, binary strings, refs/GC).

** High-level plan (produced by inventory agent 2026-06-10)

*** Pivotal constraint — userdata is byte-incompatible (all-or-nothing per type)
    LuaSwift `push(userdata:)` stores an inline `Any` box (`MemoryLayout<Any>.size`)
    under a generated metatable named `LuaSwift_Type_<T>` with a synthesized
    `__gc` that only deinits the box. The repo stores a *retained raw pointer*
    (`Unmanaged.passRetained`) under an `hs.<name>` metatable with a hand-written
    `__gc` that also unrefs callbacks / invalidates timers / closes resources.
    These models cannot be mixed on the same metatable: `lua_checkUserdataObject`
    / `lua_pushretainedUserdata` read the pointer slot and will crash on a
    LuaSwift box; `touserdata<T>` returns nil on a repo box. THEREFORE a userdata
    type must flip 100% at once — type + every producer/consumer (including the
    `hs.image` / `hs.styledtext` cross-module special-cases in
    `LuaHelpers.swift:203-225`, and any string `luaL_getmetatable("hs.foo")` /
    `core_getObjectMetatable` lookups in `LuaRuntime.swift:634`). Value
    conversion, function-table registration, and registry refs, by contrast, CAN
    migrate incrementally.

*** Mapping table (raw CLua → idiomatic LuaSwift) — the transforms each WP applies
    - C1  `[luaL_Reg]`+`strdup`+`luaL_setfuncs` → `L.setfuncs([...])` / push throwing closures
    - C2  `luaL_newmetatable`+setfuncs+`__index` → `L.register(Metatable<T>(fields:[".memberfn"...]))`
    - C3  `lua_newuserdata`+`Unmanaged.passRetained` → `L.push(userdata: obj)`  (all-or-nothing, see above)
    - C4  `luaL_checkudata`+`takeUnretainedValue` → `try L.checkArgument(i)` / `L.touserdata(i)`
    - C5  hand-written `__gc` teardown → Swift `deinit` / `Closable.close` (preserve GC-canary semantics)
    - C6  `luaL_ref`/`lua_rawgeti`/`luaL_unref` → `LuaValue` (auto-unref on deinit; invoke via `pcall`)
    - C7  `lua_pushany` → `L.push(any:)`  (keep geometry `__luaSkinType` + cross-module userdata routing)
    - C8  `lua_tovalue ... as!` → `L.tovalue(i)` / `try L.checkArgument(i)`  (round-trip tests required)
    - C9  `luaL_checkstring` (binary) → `tovalue<Data>/<[UInt8]>` / `lua_checkdata` parity (binary-safe)
    - C10 `luaL_checktype`+`lua_tonumber` → `let x: Double = try L.checkArgument(n)`
    - C11 `luaL_error` (in CFunction) → `throw L.error("…")` (only in throwing `LuaClosure` bodies)
    NOTE: `@_cdecl("luaopen_hs_lib…")` entry-point *signatures* stay C-shaped (imported by
    `@_silgen_name` in generated `HSExtensionsGenerated.swift`); only the *body* migrates.
    The idiomatic API works on the existing `luaL_newstate()` — `LuaState` is the same
    `UnsafeMutablePointer<lua_State>`; first idiomatic call lazily registers LuaSwift's
    private `_State` bookkeeping (names `LuaSwift_*`, disjoint from `hs.*`).
